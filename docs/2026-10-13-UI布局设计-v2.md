## 一、设计原则（实现时全程对照）

1. **一条信息只有一个家**：线路状态、网关状态各只画一份，其它地方引用或跳转。
2. **异常上浮**：风控/限流/额度失败集中到总览「需要关注」条，不靠用户点开抽屉发现。
3. **总览只做「看 + 一键」**，维护类操作归「模型」「设置」页。
4. **高频操作留高频位置**：退出在顶栏右上角（肌肉记忆）；一次性配置动作收进设置页。
5. **每张卡只有一个 primary 按钮，且是「下一步最可能的动作」**：停止的线路高亮「启用」；运行中的线路「停用」用普通样式（停用不该被视觉鼓励）。
6. **破坏性操作必须二次确认**（全部停止、退出、三个接管）。

## 三、页 1 · 总览（默认页，改动最大）

自上而下四块：

### ① 结论行 + 网关 hero（横贯全宽）

```
✓ 可以干活：网关运行中 · Codex 已接管 · 2/6 线路可用
────────────────────────────────────────────────────────────
统一网关 :8790   Codex ✓ · Claude Code ✓ · Claude Desktop 未接管 →设置
目录模型 6 个 · 上下文窗口 1M                      [启动] [停止]
```

- **第一行是整页存在的意义**：三秒内回答「现在能不能干活」。判定规则：
  - 网关 up 且 Codex 已接管 且 ≥1 条线路运行 → `✓ 可以干活：…`
  - 否则 → `✗ 不能干活：<第一条不满足的原因>`，行尾给对应的一键动作（如网关未启动 → `[启动网关]`）。
- 第二行状态文本整行可点 → 跳设置页（接管动作全在设置页，这里只显示状态）。
- 上下文窗口只**显示**当前值（纯文本），修改入口只在设置页。
- 数据源：`/api/status`（agg 字段）+ `/api/clients/status` + `/api/ctx/window`(GET)。

### ② 需要关注（条件渲染，无异常时整块隐藏、不占位）

```
⚠ cred-d 风控（推理被拦）
⚠ cred-c 可用但模型限流：deepseek-v4.1-flash 限流到 10:24
⚠ 国际额度查询失败（凭据过期？）
```

- 数据源：`/api/intl/creds` + `/api/credits`。
- 判定：`state==='风控'`、`!ok && until`、额度 `ok===false` 的条目逐条列出。
- 文案沿用现有 `credWhy()` 规则：**上游没给恢复时刻就不显示恢复时刻**，只给本地重试倒计时。
- 每条可点 → 跳「线路与凭证」页并自动展开对应卡的凭证抽屉（用 URL hash 定位，如 `#line-intl`）。

### ③ 线路开关（取代现有瓦片网格，改为 6 行紧凑列表）

```
线路             状态      账号/摘要            额度           操作
● 国内 WorkBuddy  运行中    账号 Gin           2,677/5,200   [停用]
● 国际 WorkBuddy  运行中    cred-b · 凭证3/4可用  100/250      [停用]
○ Qoder CN       已停止    —                  未查询        [启用]
○ Trae CN        已停止    —                  未查询        [启用]
○ Zcode          已停止    —                  （免Key）      [启用]
○ MiMo           已停止    —                  —             [启用]
```

- **停掉的线路只占一行**（行高约 34px、整行降透明度），不再是一张 3 行的卡。
- 行点击 → 跳「线路与凭证」对应卡。
- 额度列仍只在手动刷新后显示，带 `（时间）` 与差额着色；差额长时放 title tooltip，行内只留数字。
- 启停按钮强调态随状态切换（见原则 5）。

### ④ 签到条（维持现状徽章胶囊式，不动）

```
[一键签到] [国际活跃上报]  今日已签 | 国内 ✓+100 · 国际 ✓活跃+30 · …
```

- `shortCheckin()` 压缩逻辑、title 全文、`今日已签/部分成功/未签` 三态原样保留。

## 六、页 4 · 用量统计（重设计）

设计参考 Plausible / Umami 的看板风格（六大 KPI 一行、只放一张趋势图、榜单行内占比条），
保持零依赖：图表用**内联 SVG 手绘**，不引 chart.js 等 CDN（与原则「单文件无外部依赖」一致）。

### 布局

```
[今天 | 近7天 | 近30天 | 全部]（分段选择器，默认近7天）   统计走 :8790 的请求

① KPI 行（六个数字一行排开，无卡片框，竖细线分隔，Plausible 式）
──────────────────────────────────────────────────────────────
 总 tokens      输出 tokens    请求数       缓存命中率    失败率
 15.6M ▲18%     12.4M ▲9%     486 ▲5%     61%          2 · 0.4%
 输入 3.2M      思考 1.1M
──────────────────────────────────────────────────────────────
```

- 数字大（20px 加粗），变化率小字绿/红（▲绿 ▼红，失败率永远红）。
- 「总 tokens」作 hero 指标，输入/输出/思考以小字挂在对应格下方，不再各占一卡。
- **缓存命中率用百分比**，不用裸 token 数（Plausible 式：给人看的是杠杆比率）。
- **环比不需要改后端**：前端并行拉 `days=N` 与 `days=2N` 两次 `/api/usage`，
  差值即环比（「全部」档不显示变化率）。失败率 = fail/reqs 前端算。

```
② 趋势图（全页唯一一张图，占满宽度，高约 160px）
  tokens 按天堆叠柱状图（输入/输出两段堆叠，单色系两档明暗）
  ▂ ▃ ▅ ▂ ▇ ▆ █ …
  hover 出 tooltip：10-11 · 486 请求 · 输出 2.1M · 输入 0.5M
```

- 数据源 `usageData.days`；纯 SVG `<rect>` 拼柱子，CSS hover 或
  `<title>` 出明细即可，不做缩放/图例/多序列切换（保持克制）。

```
③ 榜单双栏（Umami 式：行内占比条取代裸数字表格）
┌─ 按模型 Top 10 ─────────────────┐  ┌─ 按线路 ─────────────────┐
│ gpt-5.3-codex   ████████ 45%    │  │ 国际 WorkBuddy ████ 60%   │
│                 5.6M · 210 请求  │  │              9.4M · 290  │
```

- 每行 = 名称 + 占比条（按 tokens 占比，单色 --brand，宽度即占比）+ 右侧小字
  `tokens · 请求数`。占比一眼见分晓，不再扫一列列数字。

## 八、交互细节

### toast（取代顶栏 `#msg`）

- 位置：右下角；成功 5 秒自动消失，错误 8 秒或手动点 × 关闭。
- 失败类消息（连接中断等）保留顶栏不弹的兜底：页面不可交互时至少 console 可见。实现上简单化即可：`showMsg(text, err)` 改为调 toast，其余调用点不动。

### 轮询与刷新策略（全部沿用现有口径，不许改）

| 数据 | 接口 | 策略 |
|---|---|---|
| 线路/网关状态 | `/api/status` | 2 秒轮询 |
| 昵称 | `/api/nick` | 6 秒轮询（与状态分离，理由不变） |
| 额度 | `/api/credits` | **永不自动轮询**，仅手动「刷新额度」/「刷新」（2026-10-08 风控拍板） |
| 凭证可用性 | `/api/intl/creds` | 不跟随轮询；进页拉一次 + 手动强拉 |
| 签到 | `/api/checkin`、`/api/intl/checkin` | 手动 |
| 探测 | `/api/models/probe` | 手动，30 秒超时 |
| 倍率 | `GET/POST /api/ratios` | 手动 |
| 用量 | `/api/usage?days=` | 切到用量页才拉 + 手动刷新 |
| 接管状态 | `/api/clients/status` | 进设置页 + 操作后 |
| 上下文窗口 | `GET/POST /api/ctx/window` | 进设置页读一次 |

- 顶栏「刷新」= 全刷：状态 + 昵称 + 额度(强) + 凭证可用性(强) + 目录 + 用量。
- 页面切换用现有 `switchPage()` 模式：切到某页才触发该页的首次拉取。

### 跳转定位

- 「需要关注」条目 → `#line-<key>` 跳线路页并自动展开对应卡的凭证抽屉。
- 总览 hero 第二行 → `#settings`。
- 模型页支持 `?line=<key>` 预选线路下拉。

## 九、实现方注意（既往拍板，违反即返工）

1. 额度/凭证可用性**永不自动轮询**，只手动触发（2026-10-08 风控拍板）。
2. 上游没给恢复时刻就不显示「恢复时刻」，只给本地重试倒计时（不许编）。
3. 停止的线路必须视觉降权（本设计：单行折叠；不许改回大卡）。
4. 凭证可用但模型级限流要显黄标「可用·模型限流」，不许绿 ✓ 蒙混。
5. 嵌入式单文件 HTML（`webHTML` 常量），不引外部依赖、不加构建步骤。
6. 深色模式跟随 `prefers-color-scheme`，沿用现有 CSS 变量体系（`:root` + dark 覆盖段）。
7. 现有文案资产原样迁移：`credWhy/credBadgeText/credTitle/shortCheckin` 的规则、
   倍率覆盖表说明文字、二次确认文案（全部停止/退出/接管）。
8. 后端 `/api/*` 一律不动；本设计只改 `webui.go` 的 HTML/CSS/JS。
