# 2026-10-13 融合交付：hub-go 以 sidecar 内核身份融入 Hub Switch（方案 A）

## 结论

按用户拍板执行**方案 A（进程级融合）**：hub-go 二进制作为 Hub Switch 的受管内核子进程
随应用启停，Hub Switch 侧边栏新增「线路与凭证」页统一管理五条线路、签到与新模型探测。
**桌面上从此只有 Hub Switch 一个应用**；hub-go 两万行 Go 逆向沉淀（解密/签名/流式/退避/
限流台账）原样保留，全部测试基线不动。

## 工作原理

```
Hub Switch（Tauri 桌面壳，/usr/bin/hub-switch）
 ├─ 启动 setup：ensure_core() —— :8801 已有实例则复用；否则 spawn 内核子进程
 │    （AIHUB_ROOT=<数据根>，stdout/err → ~/.cc-switch/logs/hubgo-core.log）
 ├─ watchdog：每 15s 检查，自己拉起的内核挂了自动重启（外部实例不接管）
 ├─ 退出 cleanup_before_exit：kill_core() 只带走自己拉起的子进程
 └─ 新页面「线路与凭证」（侧栏 Route 图标）：
      直接 fetch 内核 API（:8801，CORS 已放开）——
      启停/换凭证（国内双凭证+国际四凭证）/一键签到/国际活跃上报/探测新模型/重启内核
```

内核二进制定位顺序：`hubgo-core.json` 指定 → deb 资源目录（随包自带）→
`~/.cc-switch/hubgo-core/aihub` → 开发仓库 `bin/aihub`（兜底）。
数据根缺省 `/home/<user>/opt/AI_test/hub-go`，可用 `~/.cc-switch/hubgo-core.json` 覆盖：

```json
{"core_path": "", "data_root": "/home/<user>/opt/AI_test/hub-go", "enabled": true}
```

## 与既有链路的关系

- **Codex/Claude 的协议转换仍在 Hub Switch（:15721）**——本方案不动聚合层；
  hub-go 内核只负责五条线路的本地代理（8787/8795/8796/8797/8799）与控制台（8801）。
- Hub Switch 退出时：先把 Codex/Claude 客户端指回直连（原有逻辑）→ 停代理（原有）→
  杀内核子进程（新增）。
- 旧的 hub-go 独立启动方式（桌面快捷方式/命令行）依然可用：先启动的算外部实例，
  Hub Switch 会复用它而不是重复拉起。

## 遗留

1. deb 安装需 sudo（交互密码），本轮无法代办；
2. 「探测新模型」结果在 Hub Switch 页内为纯文本摘要（控制台 :8801 有完整表格版）；
3. MiMo 线路 Linux 不支持（内核本身限制，非融合引入）。
