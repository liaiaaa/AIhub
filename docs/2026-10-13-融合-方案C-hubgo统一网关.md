# 2026-10-13 融合终局（方案 C）：hub-go 吞并网关，只剩一个 aihub 进程

## 结论

按用户最终拍板，放弃 sidecar 方案（嫌 450MB 的 Tauri 壳太重），改为
**hub-go 自己吞并 Hub Switch 的网关职责**。现在：

```
aihub（单进程，常驻 ~80MB）
 ├─ :8801 控制台（线路/凭证/签到/模型探测，原有）
 ├─ 五条线路 8787/8795/8796/8797/8799（原有）
 └─ :8790 统一网关（新增能力）
      ├─ /v1/responses        → Codex（wire_api=responses，原有）
      ├─ /v1/messages         → Claude Code / Claude Desktop 3P（新增 Anthropic 转换）
      ├─ /v1/chat/completions → OpenAI 兼容客户端（原有）
      ├─ /v1/models           → 客户端模型目录（原有）
      └─ 模型名路由：白名单 + 动态「线路.模型」+ 兼容「ccs-线路/模型」「ccs-claude-<key>--<model>」
```

启动行为完全遵守用户习惯：**双击桌面 AIHub 后默认全部关闭**（线路、网关都不自启），
想用哪个在控制台手动开。

## 新增能力（相对原 :8790）

| 能力 | 说明 |
|---|---|
| Anthropic `/v1/messages` | Anthropic Messages ↔ chat completions 双向转换；支持文本/图片(base64)/工具调用(tool_use↔tool_calls/tool 消息)/thinking 块（客户端显式开启才输出）；流式逐帧转换（真增量，非假流式）+ 非流式聚合 |
| 动态模型路由 | 白名单精确命中 → `ccs-<key>/<model>` 与 `ccs-claude-<key>--<model>`（Hub Switch 时代模型名不用改）→ `<线路>.<模型>` 全线路零配置 |
| zcode 入列聚合 | 之前聚合口只有 dom/intl/qoder/trae，现在 zcode 也可挂 |
| 客户端接管 | `POST /api/clients/takeover {"app":"codex"/"claude"}`：备份原文件后把 Codex config.toml（model_provider=aihub）与 Claude settings.json（base_url→:8790）切到统一网关；`/api/clients/status` 只读展示当前指向 |
| 统一网关 UI | 「聚合与网关」页：启停、目录管理（加入/删除）、接管按钮、当前指向展示 |

## 验证记录（全部实测通过）

- `/v1/messages` 非流式（thinking on，qoder）：回复"可以"，usage 66/28
- `/v1/messages` 非流式 + 工具（dom）：`tool_use get_weather({'city':'北京'})`，stop=tool_use，usage 154/54
- `/v1/messages` 流式：Anthropic SSE 事件流（message_start/content_block_*/text_delta）正常
- `/v1/responses`（dom）：200 回复正常（intl 受上游出网 TLS 超时影响，与代码无关）
- 接管后 `~/.codex/config.toml` model_provider=aihub；`~/.claude/settings.json` base_url=:8790
- `go vet` / `go build` / `-short` 单测通过

调试中修掉的三个坑（记录备查）：
1. 裸 `cargo build` 缺 `tauri/custom-protocol` → Tauri 二进制是 dev 形态白屏（方案 A 遗产）；
2. 非流式请求把 `stream=false` 透传上游导致回包 JSON 而解析器只认 SSE → 上游恒流式；
3. `collected.build()` 返回的是 chat completion 信封（choices[0].message），误当裸 message 解包全取空；
   `json.Number` 需要 floatVal 支持。
