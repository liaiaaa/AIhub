> 触发：用户问「都说 workbuddy 国内版反代到 dsh 会被封号，怎么优化 aihub」。
> 本轮范围（用户选定）：**保号优先**——只修会被上游识别的硬伤，dom 保留可选但降级为
> 手动才用；允许用 `CodeBuddy凭证` 发 ≤5 次真实请求验证。

- 两个仓库的清洗规则与本地实测一致：上游对 system 里的
  `You are an AI agent powered by DeepSeek Harness.`、
  `You are a coding agent powered by the <model> model.`、
  `You are an AI assistant built on DeepSeek.` 做**大小写不敏感的连续子串匹配**；

  （`You are powered by …`）。

## 3. 改动

### 3.1 出站身份单一事实来源（`proxy.go`）

新增 `officialIntlWBVersion = "5.8.4"` 与四个构造函数，其它文件只引用不写字面量：

| 函数 | 值 |
|---|---|
| `officialDomUA()` | `WorkBuddy/5.8.3 WorkBuddy/5.8.3 CLI/2.161.0` |
| `officialIntlUA()` | `WorkBuddy/5.8.4 WorkBuddy AI/5.8.4 CLI/2.161.0` |
| `officialDomBillingUA()` | `WorkBuddy/5.8.3`（单段，billing 域白名单） |
| `officialCLICodeBuddyUA()` | `CLI/2.161.0 CodeBuddy/2.161.0`（目录形状） |

替换点：`proxy_cn.go` / `proxy_intl.go` 的 `UserAgent`、`credits.go`、
`cred_dom.go`（两处 billing）、`rate_limit.go` 的 intl 查询 UA、`wb_config.go`
的目录 UA；`auth.buildHeaders` 的 `Accept` 改成官方
`application/json, text/plain, */*`。

### 3.2 身份句清洗（`proxy_responses.go`）

整句正则替换为 `harnessNeutralIdentity = "You are a helpful AI assistant."`：

```go
harnessIdentityRe  = (?i)you are\s+(?:(?:an?|the)\s+)?(?:[a-z0-9_.\-]+\s+){0,3}(?:coding\s+)?(?:agent|assistant|model|bot|ai)\b[^.\n]{0,40}?\s+(?:powered\s+by|built\s+on|built\s+by|created\s+by|developed\s+by|made\s+by|trained\s+by|using)\s+[^.\n]{1,100}\.
harnessPoweredByRe = (?i)you are\s+powered\s+by\s+[^.\n]{1,100}\.
```

新增 `Proxy.SanitizeHarness`，dom 与 intl 都置位（chat 与 responses 两条路径）。
只改 system/developer，user/assistant/tool 原样；替换结果不再次命中（幂等）。
刻意**不再保留**「You are a coding agent powered by …」这句产品信息——它就是判据之一。

### 3.3 11128 不再静默重试（`proxy_retry429.go`）

- `channelBlockRetries()` 默认 **0**；`AIHUB_CHANNEL_RETRY=N` 覆盖（上限 3），
  `AIHUB_NO_CHANNEL_RETRY=1` 强制 0。
- 新增 `rateLimitRecordChannel(uid, name)`：10 分钟滑动窗口内第 3 次命中 → 按账号写
  `kind=channel`、`Until=now+30m` 的闸门；单次只计数不停摆（上游 displayMsg 自己写
  「请重新发送」，但反复命中才是风险信号）。
- 放弃重试时给客户端可行动文案（含闸门截止），不再说「隔几分钟再发通常就过」。

### 3.4 冷却闸门（`risk_gate.go`，新增）

`gateCooling(w, auth, model, rid, logger)`：`auth.Summary()` 取 uid → `rateLimitFor` →
命中则本地回 **429 + Retry-After + hub_hint**，一次都不打上游。fail-open（Summary 失败 /
uid 为空放行）。接入 `handleChat` 与 `handleResponses`。控制台凭证卡新增
「渠道拦截，暂缓到 HH:MM」状态。

### 3.5 dom 高风险标注

- `aggDisplayName` / `aggOpenAIDisplayName`：dom 显示名加 `⚠高风险 ` 前缀（幂等），
  模型 id 与路由不变。
- 控制台 `SERVICES` 的 dom 加 `risk` 字段，线路卡渲染红色「高风险·手动」徽章与说明。
- dsh profile `~/.dsh/profiles/web/cordis.patch.yml` 三个 dom 模型名改成
  「⚠高风险 … · 手动才用」（改前备份 `cordis.patch.yml.bak-*`；
  `dsh --dump-config --profile web` 已确认 3 条生效）。

## 4. 真机验证（2026-10-25 17:3x，直接打上游、不重启 hub）

| 项 | 结果 |
|---|---|
| intl 对话（新 UA） | **HTTP 200**，UA=`WorkBuddy/5.8.4 WorkBuddy AI/5.8.4 CLI/2.161.0`，返回 `deepseek-v4.1-flash` SSE |
| dom 目录（`CLI/2.161.0 CodeBuddy/2.161.0`） | **34 条，32 条带 credits** —— 与历史矩阵一致，新形状被接受 |
| dom billing（`WorkBuddy/5.8.3`） | **通过**，可用 1589.7 / 总共 4224.0 |
| dom 对话（`CodeBuddy凭证`） | **403 `11140`：Your account has been restricted due to unusual activity（账号存在异常行为，已被限制使用）** |

**关键结论：`CodeBuddy凭证` 这个国内账号在本轮验证时已经处于 11140 账号级风控。**
这不是本次 UA 改动造成的：

- 11140 是账号级标记，文案是「账号存在异常行为」，与请求内容无关；
- 同一账号的目录与 billing 请求用**新** UA 仍然通过；
- `converter-cn.log` 历史里没有一条 11140，dom 最后一次使用是 10-22，
  而 10-23 正是上游收紧识别的时间点——时间上更符合「收紧后清算历史高频使用」。

因此这条请求无法用来判断 dom 对话 UA 是否可用；它同时说明：
**「保号」对这个账号已经晚了，本轮的价值在于止损与新账号别再踩同一个坑。**
`state.json` 里当前 dom 选中凭证是 `国内workbuddy凭证`（token 已 401 过期），
所以 dom 线路本身现在也没有可用账号——本来就不该自动开。

## 5. 仍未做 / 残余风险

- **设备指纹**（qimei / `X-Device-Id-List`）：没有抓包证据，乱加更容易被识别。
- **会话 id 稳定派生**：dsh 不传会话标识，启发式派生风险大于收益。
- **多出口隔离**：同 IP 多账号并发仍是已知特征；需要代理槽，本轮未做。
- **11115 超长**：dsh 声明 1M 上下文，实测发过 1,215,032 tokens。可后续把 dsh 各模型
  `contextWindow` 降到 900K 留余量（会提前压缩，属体验取舍，未擅自改）。
- **自动签到**：ToS 风险已有注释，停不停是另一个决定。
- `hub-go-publish` 镜像未同步（等你决定要不要发布）。
