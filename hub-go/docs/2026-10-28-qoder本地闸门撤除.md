# 2026-10-28 Qoder 本地闸门撤除（并发不再限制）

## 一句话

本地并发上限默认改为 **0 = 不限制**（原为 2，多开会话时第 3 个直接吃本地 429），
拟人间隔也改成可配置项。两者都**每请求现读**，改完不用重启。

## 为什么要改

用户 2026-10-28：「别设置本地并发限制了，太妨碍我的使用了」。

原实现（2026-10-27 加固时按方案加的）是 `qoderMaxConcurrent = 2` +
`qoderMinGap = 800ms` 拟人间隔。并发 2 在 dsh 多会话 / 并行工具调用场景下
非常容易撞墙——第 3 个并发请求立刻拿到本地 429，表现就像线路断了。

## 现在的行为

| 配置 | 默认 | 环境变量 | 数据根文件 | 说明 |
|---|---|---|---|---|
| 上游并发上限 | **0（不限制）** | `QODER_MAX_CONCURRENT=N` | `qoder_max_concurrent.txt` | 0=不限；硬封顶 64；负数/非法回落 0 |
| 相邻请求最小间隔 | 800ms | `QODER_MIN_GAP_MS=N` | `qoder_min_gap.txt` | 0=不等待（不抢锁）；硬封顶 10000 |

环境变量优先于文件。文件放数据根（`/home/<user>/opt/AI_test/hub-go/`）。

**为什么间隔默认仍保留 800ms**：这是 2026-10-27 加固时特意加的拟人化措施
（官方客户端是人工点触发，不会有毫秒级连续请求）。它只增加每次请求的启动延迟，
不会像并发上限那样直接拒绝请求。如果也嫌慢：

```sh
echo 0 > /home/<user>/opt/AI_test/hub-go/qoder_min_gap.txt
```

改完下一个请求就生效，不用重启。

## 风险说明

并发不限制意味着 dsh 多会话同时打上游时，上游会看到同一账号的多个并发请求。
官方客户端是「一次对话一个请求」，并发数本身是可被上游观察到的信号。用户已知
这一取舍：易用性优先。若日后想恢复限制，写一行文件即可，无需改代码。
