# Qoder 账号快照 + 签到修复（2026-11-05）

用户要求：①「Qoder 多账号快照」做成工具，避免换号丢凭据；② 给 Qoder 和 Trae 加签到；
③ WorkBuddy 的签到他自己手动做。

## 一、为什么需要快照

Qoder 桌面端只有**一份**凭据文件：

```
~/.config/com.qodercn.app.stable/auth.v1.dat     # v11 信封：safeStorage 主密钥 + AES-128-CBC
```

在客户端换号登录时这个文件被整体覆盖，旧号的 token 直接消失。2026-11-05 实测：
注册新号后旧号 `nick…` 的凭据已经找不回来（`~/.config`、数据根、`archive/` 均无备份）。

## 二、快照实现

`hub-go/qoder_vault.go`：

| 操作 | 行为 |
|---|---|
| 保存 | 复制 `auth.v1.dat` 到 `<数据根>/qoder-accounts/<名字>/`，附 `meta.json`（昵称/uid/到期/时间/大小）。同名覆盖前留 `.bak-时间戳`。**保存前先解密验证**，解不开就不存。 |
| 列表 | 扫描目录，标出哪份与当前文件字节一致（`current`）。 |
| 切换 | 先把当前凭据自动存成 `auto-<时间戳>`（这是当初丢号的直接补救），再原子写入目标快照。 |
| 删除 | 删目录及内部 `.bak`。 |

安全性：名字做白名单校验（中英文/数字/`-_.`），杜绝 `../` 逃逸；目录 0700、文件 0600。

**边界**：快照是 safeStorage 信封，密钥绑「本机 + 本用户」。换机器或换系统用户都解不开——
这不是 bug，是 Electron safeStorage 的设计。

**使用前提**：切换前必须退出 Qoder 桌面端，否则它退出时会把内存里的旧登录态写回
`auth.v1.dat`，覆盖刚切过去的那份。控制台里切换按钮的确认框已写明这一点。

## 三、HTTP 接口

```
GET  /api/qoder/accounts            → {ok, dir, live, running, current, accounts[]}
POST /api/qoder/accounts/save       {"name":"小号"}            → 保存
POST /api/qoder/accounts/use        {"name":"小号","start":true} → 切换（可顺手重启线路）
POST /api/qoder/accounts/delete     {"name":"小号"}            → 删除
```

`use` 会重启 Qoder 线路：`QoderAuth` 在 `Start` 时把凭据读进内存（COSY 每请求签名），
不重启就还是旧 token。

控制台设置页新增「Qoder 账号快照」卡片（列表 / 存快照 / 切换 / 删除）。

## 四、签到：Qoder 之前为什么一直「已停用」

2026-10-08 把 Qoder 签到标成永久停用，理由是「活动领取反复失败」。这次查清了根因：

**campaigns 列表接口是 GET，不是 POST。**

```
POST /sash/api/v1/me/campaigns  → 404 {"errorCode":"NotFound","errorMessage":"Not found"}
GET  /sash/api/v1/me/campaigns  → 200 {"claimable":false,"campaigns":[
      {"campaignId":"01a199e1-…","actionType":"CLAIM_BENEFIT","claimStatus":"CLAIMED"},
      {"campaignId":"01a159a1-…","actionType":"VIEW_DETAILS","claimStatus":"CLAIMED"}]}
```

旧代码用 POST，404 的 body 被 `json.Unmarshal` 成空结构（`campaigns: nil`），于是
一路走到「今日无可领活动」——和「账号真的没活动」完全同形。这就是「反复失败」的真相。

领取仍然是 POST，且**幂等**：已领过的活动返回
`{"status":"CLAIMED","replayed":true,"benefit":{"kind":"CREDITS","amount":100,…}}`。

修正后：
- 列表改 GET，并按桌面端 SDK 的做法带上 `X-Machine-Id` / `X-Machine-Type`
  （SDK 里 `campaigns.list` 声明了 `requireMachineIdentity()`；不带也返回 200，但带上零成本）；
- 文案区分三种状态：`今日已领（N 个活动均已完成）` / `今日无活动（上游未下发）` / `签到成功 +100`；
- **仍然只在手动点「一键签到」时执行**，不恢复自动定时器（风控顾虑未变）。

Trae 签到本来就正常（`今日已签到`），这次只做了回归验证。

## 六、UI 位置修正（用户反馈 18:16）

用户重启后说「没看到快捷切换按钮」。原因：第一版只放在**设置页**深处，而日常操作在
「线路」页；而且当时跑的还是 18:16 那份二进制（新代码 18:17 才编出来）。

现在两处都有：

- **线路页 → Qoder 卡片内**：一行下拉（列出全部快照，标「当前」）+「切换」+「存快照」按钮，
  加载时自动填好当前昵称与快照数量；
- 设置页 → 「Qoder 账号快照」卡片：完整列表（含 uid 前 8 位、到期日、保存时间、大小）+
  切换 / 删除。

两处调用同一组接口，切换后都会 force 重取列表（缓存只在同一次渲染内复用）。

## 七、自动留档（2026-11-05 18:26）

手动存快照有个致命时机问题：**人忘记点的时刻，恰好就是换号那一刻**。
所以加了后台监听（`qoder_vault_watch.go`）：

- 每 20 秒读一次 `auth.v1.dat`，与 `qoder-accounts/_last-seen.dat` 比内容；
- 内容变了 → 先把 **`_last-seen.dat`（旧号）** 存成 `auto-<时间戳>` 快照，
  再更新基线；
- 首轮只记基线，不留档（那时没有「旧号」可救）；
- 旧内容解不开（换机器/密钥环变了）→ 不留档但更新基线，避免每轮重试坏文件。

`_last-seen.dat` 是普通文件不是目录，所以不会出现在快照列表里。

代价：每 20 秒一次 531 字节读 + 比较，可忽略。

效果：**直接在客户端退出登录、换号登录，旧号也会被自动留档**，不用先手动存。

## 八、UI 改成 WorkBuddy 同款凭证卡片（用户反馈 18:37）

用户：「现在的感觉就是太丑了，能不能改成和 workbuddy 那种多凭证一样的 ui」。

原来 Qoder 卡片里是「下拉 + 切换 + 存快照」三个控件，和 dom/intl 的凭证卡片风格不一致。
现在改成**复用同一套 `cred-card` 渲染**：

- 后端新增 `hub-go/qoder_creds.go`：`qoderCredsStatus(force) []intlCredStatus` ——
  字段与 `/api/dom/creds` **完全一致**，前端 `renderCreds('qoder')` 一行没改；
  每份快照用自己的 token 打 `/sash/api/v2/me/usage` 拿余额，带 90 秒 TTL 缓存，
  `?force=1` 才重查（与 dom 同一套节流语义）。
- 路由：`GET /api/qoder/creds`、`POST /api/qoder/cred`（点卡片=真切换）。
- `statusMap` 增 `qoder_cred`（当前生效快照名），前端据此高亮选中项。
- 选中判定：快照内容与当前 `auth.v1.dat` **字节一致**（`qoderVaultFindByContent`），
  不依赖额外状态位，切完自然就对。

状态语义（比 WorkBuddy 多三种，都是「这张票现在不能用」）：

| state | 含义 | 卡片 |
|---|---|---|
| 可用 | 上游接受该 token 且额度未用尽 | 绿 |
| 额度用尽 | `isQuotaExceeded` | 黄 |
| 登录失效 | 上游 401/403，票已废 | 红 |
| 已过期 | meta 里 `expiresAt` 已过 | 红（不打上游） |
| 解不开 | 换机器/重装后本机密钥解不开这份快照 | 红 |

一个坑记下来：`intlCredStatus.Until` 是**限流恢复时刻**专用字段，前端会渲染成
「限流到 HH:MM」。我一开始把 token 到期日塞进 Until，卡片就变成「限流中」——
假信号。现在到期日写进 `Reason`，Until 恒空（`qoder_creds_test.go` 有断言钉住）。

前端接线（`assets/console.html`）：

- `SERVICES` 里 qoder 加 `cred:true`，卡片自动出现「凭证 N/M 可用」折叠头；
- `render()` / `loadCredStatus()` / `refreshQuota()` / 「需要关注」列表 / `gotoLine()`
  五处原本硬编码 `['dom','intl']`，全部加上 `'qoder'`（漏一处就会「切了页签卡片空掉」）；
- 点 Qoder 凭证卡片走 `qoderSetCred()`：先二次确认（会写 auth.v1.dat + 重启线路），
  取消则把单选框回弹到原选中项；
- 线路卡片上只留一个文字按钮「存当前号快照」；设置页保留管理视图（列表/删除）。

实测（真上游，临时实例 18807）：

```
acct-A  可用  2000/7000  selected=true   reason=token 到 12-05 到期
acct-B    可用   400/400   selected=false
```

测试：`qoder_creds_test.go` 5 条（两份快照都显示且只选当前、401→登录失效且 Until 必须为空、
过期快照不打上游、TTL 内只查一次 + force 重查、未入库凭据不匹配任何快照）。
