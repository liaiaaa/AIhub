# 探测到 ≠ 能加入：目录模型添加死角的修复（2026-11-05）

用户报：

> 当前的 aihub 探测新模型确实可以探测到，但是没办法更新到我的目录模型里面呀。
> 比如 workbuddy 国内版探测新模型，探测到了 hy4，但是我打开目录模型那边没办法添加这个模型。

复现（现网 8801，dom 线路未启动）：

```
GET /api/models/probe      → dom up=true new_count=22，列表里有 hy4free / hy3-x / …
GET /api/agg/line_models?line=dom
  → {"models":[],"msg":"线路未启动，请先在上方启动它","ok":false}
```

## 根因：两条路径的数据源不一样

| 路径 | 数据源 | 线路没启动时 |
|---|---|---|
| 探测新模型 `/api/models/probe` | **上游实时目录**（dom/intl 走 `/v3/config`，qoder/zcode 走各自在线目录） | 照样出结果 |
| 添加下拉 `/api/agg/line_models` | **线路自己的 `/v1/models`**（要线路在跑） | `ok=false`，下拉只剩一句错误提示 |

所以「探得到、加不了」是必然的：新模型只存在于上游目录，还没进线路广告列表；
而添加界面只认线路广告列表。用户看到的不是「加不了 hy4」，是**下拉框里根本没有 hy4 这一项**。

## 修法

### 1. 后端：`apiAggLineModels` 回落 + 合并（`hub-go/proxy_agg.go`）

- 线路**没跑** → 直接返回上游探测结果，`source="upstream"` + 一句 note 说明来路；
- 线路**在跑** → 线路目录打底，再并上上游多出来的 id，`source="line+upstream"`；
- 上游也没取到 → 还是 `ok=false`，但文案说清「线路未启动且上游目录也没取到」，不假称成功。

新增两个可测的小东西：

```go
var probeLineModelIDs = func(h *Hub, line string) ([]string, map[string]string) { … }
func mergeUnique(base, extra []string) ([]string, bool)
```

`probeLineModelIDs` 做成**包级变量**是为了单测能注入假上游 —— 否则这条分支只能靠真网络测，
而它恰恰是关键分支。`mergeUnique` 内部 `append([]string(nil), base...)`，不就地改 base
（Go 里 append 共享底层数组的老坑，测试里有专门一条钉它）。

### 2. 前端：探测结果一行一个「加入目录」（`assets/console.html`）

原来探测表格里**没有任何添加按钮**，只有模型名/新标签/倍率三列。现在：

- 每个模型行一个「加入目录」按钮 → 直接 `POST /api/agg/add {line, model}`；
- 每行线路头一个「新模型全加入」→ 逐个加，带 confirm，报「已加入 N 个，失败 M 个」；
- 已在目录里的模型标 `已在目录` 徽章（数据来自 `/api/agg/models` 缓存 `aggModelsCache`，
  **不是** `state.agg` —— 那里只有个数量，第一版我写错过，靠这条才发现的）。

省掉「切页签 → 选线路 → 翻模型 → 点加入」四步。

## 验证

单测 5 条（`hub-go/agg_line_models_test.go`）：

```
TestAggLineModelsFallsBackToUpstreamWhenStopped     PASS   线路停了也能列出 hy4free + source=upstream + note + display
TestAggLineModelsStoppedAndNoUpstreamStillSaysWhy   PASS   上游也没有时不许假称成功
TestAggLineModelsUnknownLine                        PASS   未知线路 400
TestMergeUniqueAppendsOnlyNew                       PASS   只追加新项、不动 base、无新项时 appended=false
TestAggHasProbeAddPathForStoppedLine                PASS   aggAdd 不要求线路在跑；重复加入不报新增
```

真机（临时实例 18810 + 隔离数据根，dom 线路未启动）修复前后对比：

```
修复前：{"models":[],"msg":"线路未启动，请先在上方启动它","ok":false}
修复后：{"ok":true,"source":"upstream","count":37,
        "models":["hy3","hy4free","hy3-preview-agent","hy3-x",…],
        "display":{"hy4free":"Hy4"},
        "note":"线路未启动：下面是上游实时目录，可直接加入（加入只是写进目录，
               真正调用前要先在上方启动这条线路）"}
```

加入闭环（同一临时实例）：

```
POST /api/agg/add {"line":"dom","model":"hy4free"} → {"msg":"已添加 dom.hy4free","ok":true}
GET  /api/agg/models → dom.hy4free 在目录（display 带「⚠高风险」前缀，未知模型的既有标注）
再 POST 同一模型                                    → {"msg":"已存在：dom.hy4free","ok":false}
```

临时数据根用完已删除（里面复制过凭据，不留）。真实 `agg_models.json`（10 条）
全程未被这次验证改动。

一处自己写错又改回来的：note 第一版写的是「调用时线路会自动按需启动」——
**假的**。`proxy_agg.go:595` 对未启动线路返回的是 `line_not_running` 错误并让用户
去控制台启动，没有自动拉起。文案已改成「加入只是写进目录，真正调用前要先启动线路」。

## 顺带说明：加入目录后要不要启动线路

`aggAdd` 只写白名单，不要求线路在跑；但**目录里有模型 ≠ 能调用**——真调用时线路得起来
（聚合网关按 slug 前缀路由到线路端口）。所以修复后的完整路径是：

```
探测 → 加入目录（线路可以没跑） → 调用时若线路未跑，网关会报线路不可用 → 去线路页启动
```

要不要「加入时顺手把线路拉起来」是个产品选择，目前**没有**这么做（启动线路会解凭证、
占端口、可能触发上游登录态刷新，不该被一个「加入目录」按钮隐式带出来）。
